## Firefox native runtime

The v0.3.0 production Firefox ZIP was loaded unmodified as a temporary add-on
in disposable macOS profiles against Roundcube **1.6.19**, Elastic, and
GreenMail **2.1.0**. Desktop **Firefox 157.0.1** and **Firefox ESR 140.17.0**
each passed **17/17** scenarios on 2026-10-09. Mozilla `web-ext` 10.7.0 reported
zero errors, notices or warnings.

Coverage: no host access before consent; real optional-host permission prompt;
isolated and MAIN-world dynamic scripts; all labels/idempotence/Unicode;
TinyMCE HTML; draft save/reopen; reply and inline-forward inheritance;
downgrade and quoted-restriction reviews; missing-label blocking verified by
independent mailbox read-back; classified delivery with both marks;
profile preview/import/actual export download and rejected malformed import;
independent composer tabs; unsupported pages; popup rendering; disabling and
revoking access. Reports: `tests/firefox/artifacts/{stable,esr}/report.json`.

CI also runs both versions on Linux; those results must be checked separately.
Permanent signed installation, Firefox Android, Windows Firefox, toolbar-popup
interaction and administrator policy provisioning have not been executed here.

## Thunderbird native runtime

The separate MailExtension requires Thunderbird **140+**. The v0.2.0 run on
**140.17.0 ESR macOS**, dated 2026-10-09, passed **20/20 native checks**.
Expanded GitHub CI passed on **Linux (20/20)** and **Windows (18/18)** on the
same ESR version; Windows omits the two optional IMAP checks. Other Thunderbird
releases are not claimed as validated. These results were recorded before the
repository was recreated; historical CI runs are not part of this repository.

The runner uses a disposable profile, synthetic accounts/keys, loopback SMTP
and an optional loopback GreenMail 2.1.0 IMAP fixture. Test permissions and the
reporting experiment exist only in a temporary copy; the production XPI is
also installed permanently and checked for compose/storage permissions only.

Coverage: plain/HTML marking, recipients/signatures/quotes/attachments,
independent composers, review cancellation and explicit approval, blocking,
marked delivery, local draft reopening, source inheritance, Send Later,
automatic defaults and removal of an approved level while a draft is open.
Inline PNGs are checked in delivered MIME; signed/encrypted OpenPGP mail is
cryptographically verified and decrypted. Encrypted IMAP drafts save/reopen;
a separate IMAP connection fetches the remote draft and it decrypts intact.
Exactly five approved messages reach SMTP. No cancelled/blocked mail arrives.

Windows CI runs the same suite without the optional IMAP fixture. It is a
required dependency auto-merge check. Linux CI runs with IMAP. Output:
`tests/thunderbird/artifacts/report.json` and runtime diagnostics.

**Partial manual acceptance:** the production toolbar picker opened on macOS.
Keyboard controls and every settings control remain pending: after the Mac was
unlocked, native automation lost popup focus and screen capture failed. Also untested:
S/MIME, production IMAP servers, newer Thunderbird versions. Profile preview,
validation and save behaviour have shared DOM tests; browser import/export
has a real-browser acceptance scenario. See [BETA-TESTING.md](BETA-TESTING.md).

## Roundcube versions

Only **1.6.19** has been executed. The integration points used are stable across
the 1.6.x line and earlier 1.x releases:

- composer fields `_subject`, `_message`, `_is_html`;
- `#composebody` textarea and TinyMCE iframe;
- `rcmail.command('send' | 'savedraft', …)` controls;
- `rcmail.env.compose_mode` (public environment value).

Older or newer versions are **not** claimed as validated.

## Known environment limitations

- The E2E suite requires Docker to run the Roundcube + GreenMail stack. Without
  Docker, unit and integration tests still run.
- The MAIN-world probe requires Chrome 111+ (the manifest requires 116+).
- Automatic draft save is exercised indirectly (via explicit Save) because it
  cannot be intercepted from the isolated world; correctness relies on
  idempotent marking, covered by unit and integration tests.
